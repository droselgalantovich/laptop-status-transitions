# Статусы ноутбука на складе

Тестовое задание: функция на TypeScript для изменения статуса ноутбука с проверкой допустимых переходов и записью истории. Условия — в [TZ.md](./TZ.md).

## План реализации

1. Определить типы статусов, ноутбука и записи истории; описать решения по неоднозначностям, включая границу срока возврата и формат ошибок.
2. Реализовать разрешённые переходы и возврат не позднее 14 дней после последней продажи, предусмотрев передачу времени для воспроизводимых тестов.
3. Добавить запись предыдущего статуса, нового статуса и даты при успешном переходе; при ошибке сохранять статус и историю без изменений.
4. Написать и запустить тесты для всех переходов, границы 14 дней, истории и повторной продажи; проверить типы TypeScript.
5. Дополнить README командами запуска, ответами о неясностях задания и использованных запросах к AI; проверить готовность репозитория к сдаче.

## Установка и проверка

Нужны Node.js и npm.

```bash
npm ci
npm test
npm run typecheck
```

Тесты проверяют разрешённые и запрещённые переходы, историю изменений,
границу срока возврата, повторную продажу и ошибки дат.

## Использование

```ts
import { changeLaptopStatus, type Laptop } from './src/laptop';

const laptop: Laptop = {
    status: 'На складе',
    history: [],
};

const result = changeLaptopStatus(laptop, 'Продан');

if (!result.ok) {
    console.error(result.error);
}
```

Функция изменяет переданный объект ноутбука и добавляет запись в его историю.
При ошибке объект остаётся без изменений.

Третий аргумент — дата изменения. По умолчанию используется текущее время;
в тестах дата передаётся явно.

## Что было непонятно и как это решено

- В ТЗ не уточняется способ расчёта срока возврата. Принял 14 × 24 часа с момента последней продажи, включая точную границу срока.
- Формат ошибки не задан. Выбрал результат `{ ok: true } | { ok: false; error: string }`: отказ в переходе — ожидаемый сценарий, который вызывающий код обрабатывает явно. При отказе статус и история не меняются..
